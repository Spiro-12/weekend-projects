# Fleet Planner Protocol v1

The contracts every track follows. **Frozen at the end of Phase 0.** Only the lead changes them, in one commit that updates this file, `src/contracts/types.ts`, `src/contracts/validate.ts` and `fixtures/` together. Planned bump: Phase 2a (split screen, sweep, demo, stress).

- Types (source of truth): `src/contracts/types.ts`
- Validators: `src/contracts/validate.ts`
- Examples: `data/` and `fixtures/`

## §1 Units, time, state
- **Tick** = 0.5 s of warehouse time (`TICK_MS = 500`, `TICKS_PER_HOUR = 7200`).
- **Cell** = 1.5 m (`CELL_MM = 1500`). One agent per cell. A moving agent holds both its cell and the cell it is moving into until it arrives. **Nobody may start a move into a cell that is being left** (causal PIBT), so followers keep one empty cell of spacing.
- **Sim state is integers only:**
  - positions: cell indices `y * width + x`
  - money: cents (economics) or whole dollars (inputs)
  - battery: `batteryTicksLeft` (percent only in snapshots)
  - **speed:** millimetres per tick, `round(speedMps × 500)`. Each agent carries its leftover distance (`src/sim/motion.ts → moveTicks`) **only while moving continuously in a straight line**; a stop or any turn resets it to 0 (even for agents with `turnTicks` 0). Move durations alternate and the average speed is exact (AMR 3 ticks/cell, humanoid 4,4,4,3, driver 3,2,2,2,3…).
- **Turns:** `AgentSpec.turnTicks` extra ticks per 90° (AMR 1, forklift and driver 2, others 0).
- `hash()` throws if any state number is not an integer.
- **Conversions** to m/s, $, % happen in UI code only.

## §2 Agent specs (`data/agents.json`, `fp-agents v1`) and sources (`data/sources.json`)
- **Agent types:**

  | Type | Who |
  |---|---|
  | `amr` | cart robot |
  | `forklift` | autonomous forklift |
  | `humanoid` | humanoid robot |
  | `picker` | person |
  | `driver` | person driving a manual forklift |

- **Per type:**
  - identity: `kind` (robot/human), `model` (render key; `code:` = built in code), `basedOn[]` (real products the numbers come from; shown in hovers, never as branding)
  - movement: `passClass` (`small` / `forklift` / `human`), `speedMps` (in shared aisles), `topSpeedMps`, `payloadKg`, `safetyCells` (forklift 1), `turnTicks`
  - work: `can[]` (`pick`, `carry_tote`, `carry_pallet`), `pickSecPerLine`, `palletSecPerMove`, `handoffSec`
  - `battery {runtimeH, chargeH, chargeAtPct}` (robots)
  - `cost {buyUsd, raasUsdPerMonth, raasSetupUsd, maintPctPerYear, softwareUsdPerYear, integrationUsd, wageUsdPerHour, equipmentUsd}`
- **`labor`:** `laborLoad` (0.46 ⇒ wage × 1.46, BLS ECEC), `supervisor {wageUsdPerHour, minPerReset}`, `packer {wageUsdPerHour}`, `turnoverPctPerYear`.
- **Every number is `Sourced` = `{ value, unit, src, note?, range? }`:**
  - `src` is a `sources.json` id, or `'estimate'`. An estimate needs a `note` with the reasoning, and usually a `range`.
  - `tests/unit/contracts.test.ts` fails on any number without a source, any estimate without a note, any unknown source id, or a value outside its range.
- **`sources.json`:** `{ id, title, publisher, url, date, accessed }`.

## §3 Layout (`data/layouts/*.json`, `fp-layout v1`)
- Generated by `scripts/layout-gen.ts` from `src/sim/layout-gen.ts`; a test checks the files match the generator.
- An ASCII grid, one character per cell:

  | Char | Meaning |
  |---|---|
  | `#` | rack (blocked; aisle cells beside it are pick faces) |
  | `.` | narrow aisle (robots and people, no forklifts) |
  | `=` | forklift-rated aisle (everyone) |
  | `D` | dock door (blocked; served from the staging cell below) |
  | `S` | staging (everyone) |
  | `P` | pack station (blocked; served from a neighbour) |
  | `C` | charger pocket (robots only, entered only as a goal) |
  | `K` | parking pocket (robots only, entered only as a goal) |
  | `X` | wall, column or conveyor (blocked) |
  | `> < ^ v` | one-way hint on a `=` cell (one-brain guidance only) |

- **Shape:**
  - picking aisles are 2 cells wide (3 m: people and robots pass); cross aisles 3 cells; **the pack lane is 2 cells wide** (spike b: a 1-wide lane was the main hotspot in both modes)
  - racks run back to back between aisles
  - the pack zone is at the bottom, docks across the top
- **Also:**
  - `racks {levels, heightMm}`
  - `zones[] {id, label, kind, x, y, w, h}`; kinds `storage | pack | dock | charge | park | conveyor`; zone `charge-forklift` marks forklift chargers
  - `aisles`, `cellMm`
- **Presets:** `small` (8 aisles, 38×31), `default` (14 aisles, 62×35, about 93 × 53 m), `large` (22 aisles, 94×47).
- **`src/sim/world.ts`** builds the graph:
  - per-class passable cells
  - 4-neighbours in fixed E, S, W, N order
  - pick faces ranked by walking distance from packing (ABC slotting)
  - pack stations and docks with their service cells
  - chargers and parking pockets with their entry cell and class
  - `humanHome` cells
  - `DistanceCache` (cached BFS per (class, goal); pockets are entered only as the goal)

## §4 Scenario (`data/scenarios/*.json`, `fp-scenario v1`)
See `src/contracts/types.ts → Scenario` and `data/scenarios/default.json`. Key rules:
- **`orders`:**
  - `mode: 'demand'`: orders arrive at `perHour`.
  - `mode: 'saturate'`: the queue is always full, which measures **capacity**.
  - `linesWeights`: integer weights for 1, 2, 3 … lines per order.
  - `sku {aPct, aPicksPct}`: ABC skew (20% of faces get 80% of picks).
- **`pallets {linesPerReplenish, inboundPerHour}`:** forklift work.
- **`pack {stations, secPerOrder}`:** packers are the same labor in every option.
- **`fleet`:** a count per agent type.
- **`vendors`:** per robot type, `[{id: 'A', pct: 60}, …]`. Ids are single capital letters; percentages add to 100; counts are split by largest remainder.
- **`traffic {mode, silo}`:**
  - `mode`: `central` (one brain), `siloed` (many brains) or `shared-status` (ISO 21423 level, Phase 2)
  - `silo` = the many-brains recovery-ladder knobs ("how smart are the vendors' robots"): `sensorCells`, `waitTicks`, `resetMin`, `retaskSec` (the vendor fleet manager's job timeout, the main gap knob). Presets (spike b, default fleet):

    | Preset | Knobs | Many brains vs one brain |
    |---|---|---|
    | smart | `retaskSec 60`, `waitTicks 3` | 7 to 9% fewer tasks/h |
    | **typical (default)** | `retaskSec 90`, `waitTicks 5` | 11 to 12% fewer |
    | poor | `retaskSec 120`, `waitTicks 8` | 17 to 26% fewer, with 7 to 10 manual resets/h |

    The gap grows with crowding (spike b, large layout: 6.7% at 30 robots, 64.5% at 60 while one brain still gains). The 10 to 40% band is our judgment; no public field data exists.
- **`economics {financing: buy|raas, baseline: 'auto' | {picker, driver}}`:** `auto` = the smallest all-human crew that keeps up, on the same orders.
- **`events`:**
  - Phase 1: `breakdown {atMin, agent, forMin}`, where `agent` is `'<type>:<n>'` (the n-th agent of that type in spawn order, 0-based; validated)
  - Phase 2: `personInAisle`, `chargers`, `orderSurge {factorPct}`
  - The default scenario has **no events**.
- **`expect`** (golden files only): ranges for `oph`, `capacityOph`, `deadlocks`, `pickerUplift`, plus `keepsUp`, `backlogGrows`, `robotCostUsd`.
- `validateScenario()` lists every problem in plain words. The AI consultant (Phase 3) uses it too.

## §5 Sim API (`src/sim/index.ts`)
- `createSim(scenario, {agents, layout}, impl?) → Sim`. Phase 0 default impl is `fake` (FakeSim); Phase 1 integration switches it to `core`.
- **`Sim`:**
  - `tick`, `step(n)`
  - `command(c)`: applied at the start of the next tick and logged with that tick
  - `commandLog()`, `snapshot()`, `drainEvents()`, `hash()`
- **Commands:**
  - `setFleet {type, count, vendor?}`: new robots appear at free cells (parking first); removed ones finish their task, then leave
  - `setOrderRate {perHour}`, `setTraffic {mode}`, `inject {event}`
- **Snapshot** (plain data, structured-clone safe):
  - `tick`, `width`, `height`
  - `agents[]`: `id, name, type, vendor, model, cell, to, moveStart, moveEnd, heading (0 E, 1 S, 2 W, 3 N), state, goal, route (next ≤ 12 cells along the distance gradient), taskId, cargo, batteryPct, blockedTicks`
  - `tasks[] {id, kind, orderIds, lines, stage, createdTick, agentIds}`
  - `stats.ticksByState[type][state]`
  - `openOrders`, `shippedOrders`, `chargers[] {cell, vendor, agentId}`
  - `deadlocks[] {ids, sinceTick}`
  - `heat` (blocked agent-ticks per cell)
- **Agent states:** `idle`, `travel`, `work`, `wait` (e.g. an AMR waiting for a picker), `blocked` (wants to move, can't), `charge`, `broken`. `AgentView.waitOn` = the agent it waits for (wait-for graph), or -1.
- **Events** (`SimEvent`, all with `tick`): `orderArrived`, `orderPacked`, `orderShipped {arrivedTick}`, `taskAssigned`, `pickDone`, `toteDelivered`, `palletMoved`, `jamStart/End`, `deadlockStart/End`, `manualReset`, `retask`, `safetyStop`, `yield`, `chargeStart/End`, `breakdown/repair`, `personInAisle`.
- **`Sim.stats()`:** cheap counters for the KPI recorder: `tick, openOrders, shippedOrders, ticksByState, unitsPicked, fleet`.
- **People are cell agents, not in the robot planner.** The sim core moves them first each tick along the `human` distance gradient, then hands the planner `occ` and `yields`. **Drivers** (people on manual forklifts) are moved the same way but use the `forklift` pass class and keep a safety cell; robots treat them like people. Shared rules for **both** traffic modes (spike b found each one necessary; none favours one brain):
  1. Robots treat people's cells (and their move targets) as fixed obstacles.
  2. **Robots yield to people:** a person blocked by a robot asks it to make way (`yields`); the planner pushes it.
  3. **Robot cell claim:** a robot that has waited 3+ ticks claims the cell it wants and people let it go first.
  4. **People's manners:** step to the side (not back) after 4 blocked ticks; two people head-on swap; wait for an agent that is already leaving; don't crowd a busy goal (wait 2 cells back).
  5. **Local detours for every robot** blocked `waitTicks` by something it can't negotiate with (a person, a parked robot; in many brains also foreign robots).
  6. PIBT pushes a robot out of a forklift's needed safety cell.
  7. Tie-break toward fewer turns.
  8. **The WMS sends each tote to the least-loaded pack station** (always on, both modes).
- **Work model (Phase 1):** with cart robots, **pickers stay in their pick zones** and meet AMRs at faces (the Locus model); only AMRs and humanoids visit pack stations. Without cart robots (people only), pickers push carts and walk to pack stations themselves.
- **Shared, lead-owned modules:**
  - `world.ts` (graph, distances)
  - `motion.ts` (speed, turns)
  - `detect.ts` (inputs indexed by position; pass `ids` to get agent ids back):
    - **deadlock** = a wait-for cycle lasting ≥ 10 ticks
    - **jam** = ≥ 3 agents stopped ≥ 20 ticks within 5 cells
  - `rng.ts`
- **`TrafficController`** (`src/sim/traffic/types.ts`, frozen from spike b's working shape), between Track A (core) and Tracks B and G (planners). The controller never mutates sim state.
  - **Input:** `{tick, world, dist, agents (robot views by id), order (sim-owned priority: oldest goal tick, then a seeded tie-break redrawn at each goal, then id), ready, occ, yields}`.
  - **Each tick, two calls:**
    1. `recover(input) → {resets, retasks}`: the sim applies them before planning.
    2. `plan(input, out)` fills `moveTo / safety / dir / want` per agent, plus `events`.
  - `stateWords()` feeds `hash()`.
  - **`TrafficEvent` mapping:** `safetyStop` → `SimEvent safetyStop`; `yield` (cell = the person's cell) → `SimEvent yield` with that person's id; `detour` and `stepAside` are internal (counted, not `SimEvent`s).
  - **Implementations:**
    - `traffic/naive.ts`: lead stub (gradient step into a free cell, no recovery), so Track A runs before B lands
    - `traffic/central/`: Track B, one PIBT over every robot
    - `traffic/siloed/`: Track G (Phase 2), one PIBT per vendor + physical layer + recovery ladder
  - **Reference implementation:** `spikes/b-traffic/src/traffic.ts`.
- **Assignment:** greedy nearest-idle by default (both modes). One brain may use batch optimal assignment capped at 32 robots per batch (Phase 2; 150 × 150 optimal costs 28 s per shift).

## §6 Runner and KPIs (`src/host/runner/`)
- **`Runner.evaluate(settings, {saturate?}) → RunResult`** is the single source of numbers: KPI tiles, money panel, compare bar, sweep and golden tests all use it.
  - Results are cached by **`runKey`** = `settingsHash` of the settings without `economics` (FNV over canonical JSON, ignoring `name` and `expect`), so a buy/rent toggle recomputes only the money, never the run.
  - Runs happen in Web Workers (browser) or inline (Node).
  - **Run window:** `warmupMin` (30) + `measureMin` (120). Battery levels start spread between `chargeAtPct` and full (seeded `battery` stream), so charging shows up within the window.
- **`RunResult`:** `scenarioId, settingsHash, kpis, fleet, traffic, hash, ticks, simMs`.
- **`Kpis`** (measured over the window):

  | KPI | Definition |
  |---|---|
  | `oph` | shipped orders ÷ window hours (capped by demand by definition) |
  | `capacityOph` | `oph` with `orders.mode: 'saturate'`. **Used for the one-vs-many band, picker uplift, the sweep knee and overload tests.** |
  | `robotUtilizationPct` | Σ robot `travel` + `work` ticks ÷ Σ robot ticks not `broken` |
  | `byType[type]` | `utilizationPct, idlePct, blockedPct, waitPct, chargingPct, brokenPct` from `ticksByState` |
  | `jamsPerHour` | jam starts ÷ window hours |
  | `deadlocksPerShift` | deadlock starts ÷ window hours × hoursPerShift |
  | `avgOrderSec`, `p90OrderSec` | (ship tick − arrive tick) × 0.5 s for orders shipped in the window |
  | `backlogEnd` | open orders at the end of the window |
  | `backlogTrendPerHour` | least-squares slope of open orders over the window. **`keepsUp`** = trend ≤ +2% of demand per hour. |
  | `pickerUplift` | units per picker-hour with AMRs ÷ people-only units per picker-hour, both at capacity. **An output, not an input**: it comes from walk speed, `pickSecPerLine` and zones, calibrated so the default lands near 75 → 135 units/h. |
  | `unitsPerPickerHour`, `resetsPerHour`, `retasksPerHour`, `deadlocksOver2MinPerShift` | |

- **`fp-sweep v1`** = `{ axes, base, results: RunResult[] }`.
- **The fake runner** (`createFakeRunner`) returns toy numbers for UI work; the UI shows **"demo data"** whenever `host.demoData` is true. Like the real runner, it fills `capacityOph` only on saturate runs and never `pickerUplift` (computed from two capacity runs).
- **Host signals:** `result` + `pending` (the run), `baseline` + `money` + **`moneyPending`** (true until the baseline search and money report finish).

## §7 Economics (`src/econ/`, Track C)
Pure functions. Each returns `Explained = { value, unit, formula, inputs: [{label, value, unit, from: 'source:<id>' | 'estimate' | 'sim' | 'user', note?}], note?, flag? }`. **`value` is `null` exactly when `flag` is set** (no NaN or Infinity, so it survives JSON). Hovers render the formula, the inputs and the source links.
- `H` = hoursPerShift × shiftsPerDay × daysPerYear.
- **Labor per year** = Σ people count × H × wage × (1 + laborLoad), plus resets (resetsPerHour × H × minPerReset ÷ 60 × supervisor wage). Packers are listed but identical in every option.
- **Buy:**
  - capex = Σ robots × (buyUsd + integrationUsd), plus drivers' equipment
  - robot opex/yr = Σ robots × (buyUsd × maintPct + softwareUsdPerYear)
- **Rent (RaaS):**
  - capex = Σ robots × (`raasSetupUsd` if the spec has one, else `integrationUsd`)
  - opex/yr = Σ robots × raasUsdPerMonth × 12
- **Annual cost** = labor + robot opex. **Savings/yr** S = annual cost(baseline) − annual cost(candidate).
- **Payback (months)** = capex ÷ (S ÷ 12).
  - `flag: 'never'` when S ≤ 0.
  - `flag: 'doesntKeepUp'` (no number) when the candidate doesn't keep up.
  - The baseline is auto-sized so it always keeps up; if a user-set baseline doesn't, it is flagged too.
- **3-year net savings** = 3 × S − capex.
- **Cost per order** = annual cost ÷ (OPH × H).
- **Best mix** = highest 3-year net savings among fleets that keep up. Never ranked by payback: renting "pays back" instantly.
- **Not modeled** (listed in every money hover): taxes, depreciation, discounting, interest, residual value, building changes.

## §8 Seeds and determinism
- A master `seed` (uint32) feeds SplitMix32, which derives named sfc32 streams (`stream(seed, name)`): `arrivals`, `humans`, `faults`, `battery`, `physical`, `spawn`, `tiebreak:<vendor>`, `ladder:<vendor>`.
- **Arrivals:** exactly **4 draws per tick** from `arrivals`. Each draw `int(28800) < perHour` adds one order, which supports up to 28,800 orders/h. Rate changes never shift later draws.
- **Order contents** come from the counter-based `hash32(seed, n, …)`, so order #n is identical at every rate and every fleet. These are **common random numbers**: both sides of the split screen and every sweep point see the same orders.
- Same scenario + seed + command log ⇒ the same `hash()` in Node, Chromium, Firefox and WebKit. `tests/e2e/determinism.spec.ts` checks this in CI.
- **Banned in `src/sim`, `src/kpi`, `src/econ`, `src/contracts`** (`tests/unit/purity.test.ts`):
  - `Math.random`, `Date`, `performance.now`
  - `Math.sin/cos/tan/exp/log/pow/sqrt/hypot/atan2/…` and `**`
  - importing three
- **Plus:**
  - `tsconfig.sim.json` compiles those folders with no DOM and no node types
  - sorts end with an agent-id tie-break
  - no iteration over unsorted `Map`/`Set` in planning

## §9 Render and UI (lead-owned cores)
- **`src/render/core/renderer.ts`:**
  - `createRenderer(container, {tier}) → { renderer, scene, roots {world, agents, fx}, views, perf, tiers, addView, setViews, onFrame, setRenderPass, info, setTier }`
  - One WebGL2 renderer; views are scissor rectangles, each with its own camera and render layers. Layer 0 is the shared world; split-screen sides use layers 1 and 2.
- **`src/render/core/camera.ts`:** `CameraRig`:
  - `overview()` (fits the building for the aspect ratio; portrait looks from the long side)
  - `follow(() => {pos, yaw})` (chase cam behind the agent, down the aisle; dragging lets go)
  - `flyTo(pose, ms)`, `pose()`, `distance()`
- **Grid ↔ world** (`geom.ts`): x = (col + 0.5 − W/2) × 1.5, z = (row + 0.5 − H/2) × 1.5, Y up.
- **Agent rendering** interpolates from the latest snapshot at `live.renderTick` = `sim.tick − 1 + accumulated/500 ms`: position = lerp(cell, to, (renderTick − moveStart) ÷ (moveEnd − moveStart)).
- **Tiers** (tuned by spike a on Spiro's M2 Air):

  | Tier | DPR | Effects |
  |---|---|---|
  | high | ≤ 1.5 | half-size bloom, agent shadow map |
  | medium (desktop default) | ≤ 1.5 | glow ribbons, blob shadows |
  | low (touch / small screens) | 1 | far racks drop upper boxes, simple people |
  | lite | 0.75 | |

  - Full-size bloom at DPR 2 costs about 8 ms of GPU on the M2 Air, so high never uses it.
  - **Demote** when the frame interval runs > 20 ms for 2 s.
  - **Promote** only when GPU timing exists and CPU p95 + GPU p50 × (next tier's cost ratio: high/medium 2.7, medium/low 1.3) < 14 ms for 5 s. Never without timer queries (iOS Safari). Not for 60 s after a demotion.
  - `?tier=` freezes it.
  - A lost WebGL context shows a reload card that reopens in lite. No WebGL shows a friendly message.
- **`LiveSim.reset(scenario, data)`** restarts in place: the same object, listeners, speed and pause survive a scenario or layout change; the selection is cleared.
- **People are rendered as instanced rigid parts** with a procedural walk (40 people: 23 draw calls, 1.4 ms CPU), not skinned clones (779 draw calls, 12.4 ms). At most one skinned "hero" worker, for the followed person.
- **Panels:** every file in `src/ui/panels/*.tsx` default-exports `definePanel({ id, slot, order, title, Component, when? })`.
  - Slots: `kpi`, `left`, `right`, `bottom`, `overlay`.
  - On phones, `left`/`right`/`bottom` become bottom-sheet tabs.
  - Panels get `host` (signals: `settings`, `result`, `pending`, `selected`, `speed`, `paused`; methods: `setFleet`, `peopleOnly`, `setOrderRate`, `setTraffic`, `setFinancing`, `setScenario`, `setSpeed`, `setPaused`, `select`).
- **Asset manifest** `public/assets/manifest.json`: `{format, v, source (pinned revisions), decoder, models: {key → {url, urlLo?, scale, offset, size, tris, trisLo?, drawCalls, bytes, gzBytes, gzBytesLo?, parts[], clips?, license, credit, source, firstTier, label}}}`. In-app credits read it.
- **Shared asset loader** `src/render/core/assets.ts`: `assetLoader(baseUrl)` → typed manifest (one fetch), one GLTFLoader with the meshopt decoder, a cache per URL, `urlFor(key, tier)` (low/lite use `urlLo`). Tracks D and E load only through it.
- **Layers** (`src/render/core/layers.ts`): `WorldLayer` (`createWorldLayer` in `render/world/index.ts`, Track D) and `AgentLayer` (`createAgentLayer` in `render/agents/index.ts`, Track E), each with optional `debug()`; the agent layer also has `inject(snapshot | null)` for tests. `followTarget()` may return `distance`/`height` to change the chase framing.
- **Overlay slot:** panels in `overlay` position their own content (`position: absolute`); the section itself never blocks clicks.

## §12 Decisions from the Phase 0 spikes
Full numbers: `spikes/b-traffic/RESULTS.md`, `spikes/c-assets-RESULTS.md`, `spikes/a-render/RESULTS.md`.

**Spike b (traffic):**
- Keep 0.5 s ticks and 1.5 m cells.
- PIBT works in both modes. Planner cost is 0.04 to 0.09 ms/tick at 150 robots; whole tick about 0.14 ms (detection included); 8 h shift ≤ 8 s.
- The many-brains gap is 11.6% at the default fleet with typical vendors, and grows with crowding.
- Identical hashes in Node, Chromium, Firefox and WebKit.
- Budget change: whole tick ≤ 0.2 ms at 150 robots + people in both modes (the planner alone ≤ 0.1). The jam detector is now bucketed, O(n).

**Spike c (assets):**
- Sizes, gzipped: first tier 1.33 MB (budget 4), everything 2.01 MB (15), phone 0.43 MB (2).
- SimReady pallets, cartons, totes, conveyor, pack table, dock gate, guard rail, light panel, column, counterbalance forklift and walk-behind stacker, all CC BY 4.0 from a pinned revision.
- In-rack loads are composed from a pallet plus 50-triangle cartons (decimated SimReady assemblies crumpled).
- **Built in code:** AMR, humanoid and the autonomous forklift dressing (`src/render/models/`).
- **Worker:** Quaternius CC0 with a hi-vis vest (12.6k triangles, walk/idle/push clips, 139 KB).

**Spike a (render):**
- **Medium tier holds 60 fps in split screen** with 150 robots + 40 people per side (46 draw calls, thin headroom). **High as first specified (DPR 2 + full bloom) does not**, so high is now DPR 1.5 with half-size bloom, and medium is the desktop default.
- **People:** instanced rigid parts, not skinned (see §9).
- **The perf harness is kept:** `scripts/perf.ts` + `tests/perf/`.
  - New headless Chromium uses the real Apple M2 GPU via Metal; the harness refuses software GL.
  - **The GPU timer query reads high on ANGLE/Metal** (it spans idle gaps), so gates use **sync mode** (`--sync`: 1-pixel readback per frame) and `work` p95, plus dropped frames ≤ 0.5% in the normal loop.
  - Restart `serve-gz` after rebuilds is no longer needed (it now caches by file mtime).
- **Budgets tightened:** triangles ≤ 1.5M (both views), initial JS ≤ 250 KB gz.
- **Keep procedural racks for the far field:** a SimReady rack GLB would add about 1.1M triangles per view.
