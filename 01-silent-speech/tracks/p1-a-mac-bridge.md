# Track A: Mac bridge app (SilentSpeechBridge)

## Goal
A tiny macOS 14+ SwiftUI app that reads AirPods Pro 3 head motion with `CMHeadphoneMotionManager` and streams it over a WebSocket server on `ws://localhost:8765`, exactly per `PROTOCOL.md` §2. It also receives action requests (stub runner this phase).

**Important:** the agent writing this cannot compile Swift (Linux container). The lead compiles it on GitHub CI (macOS job in `.github/workflows/ci.yml`, `xcodebuild -target SilentSpeechBridge CODE_SIGNING_ALLOWED=NO`) and on Spiro's Mac through Remote Control. Spiro is not technical and never builds anything himself. So: small files, stable APIs, no clever generics, no third party packages. Write it like it must compile on the first try. Swift language mode 5 (avoid Swift 6 strict concurrency errors).

## Owns
`mac/project.yml`, `mac/SETUP.md`, `mac/actions.example.json`, `mac/SilentSpeechBridge/{App,ContentView,MotionStreamer,WebSocketServer,ActionRunner}.swift`, `Info.plist`, `SilentSpeechBridge.entitlements`. Read only: `mac/SilentSpeechBridge/Protocol.swift` (use its types, don't change it).

## Build
- **XcodeGen** `project.yml`: macOS app, deployment target 14.0, bundle id `com.spiro.SilentSpeechBridge`, `SWIFT_VERSION: 5.0`, `ENABLE_HARDENED_RUNTIME: NO`, App Sandbox **off** (entitlements file with `com.apple.security.app-sandbox = false`), `CODE_SIGN_STYLE: Manual`, `CODE_SIGN_IDENTITY: "-"` (ad hoc default, so it always builds), no `DEVELOPMENT_TEAM`, `INFOPLIST_FILE` pointing at our Info.plist.
- Info.plist: `NSMotionUsageDescription` ("Reads your AirPods head motion to recognize silent speech."), `NSAppleEventsUsageDescription` ("Sends texts, changes volume and plays music when you silently say a command.").

## Files
- **MotionStreamer.swift**: `CMHeadphoneMotionManager` + `CMHeadphoneMotionManagerDelegate` (connect / disconnect). `startDeviceMotionUpdates(to: OperationQueue)`. Don't assume 25 Hz: a first real test showed AirPods Pro 3 streaming at ~50 Hz on iPhone. Send every sample as it arrives. Per sample build a `MotionMessage` (seq += 1, `t = motion.timestamp`, quaternion w,x,y,z, rotationRate, userAcceleration, gravity), all through `r5`. Map `sensorLocation` → `BudLocation`, `CMHeadphoneMotionManager.authorizationStatus()` → `AuthState`, `isDeviceMotionAvailable` false → `unavailable`. Measures hz (samples in last 2 s / 2) and gapPct (intervals > 60 ms over last 10 s). **Simulate motion** mode: a Timer at 50 Hz making sine wave samples (so the WebSocket can be tested without AirPods); `t = ProcessInfo.processInfo.systemUptime` (same clock as `CMLogItem.timestamp`), `seq` keeps counting across mode switches; `status.simulated = true`.
- **WebSocketServer.swift**: `NWListener` with `NWProtocolWebSocket.Options` (`autoReplyPing = true`) on port 8765, `params.requiredInterfaceType = .loopback`, `allowLocalEndpointReuse = true`. Origin check in `setClientRequestHandler`: find the Origin header **case insensitively**; accept only if it is in `ProtocolV1.allowedOrigins`; if missing, accept only when the "Allow non browser clients" toggle is on (default off). In `newConnectionHandler`, **cancel any connection whose remote endpoint host is not 127.0.0.1 or ::1** (belt and braces on top of `.loopback`). Track connections; on new connection send `hello` then `status`. `broadcast(text:)` for motion. Receive loop: a valid JSON object whose `type` is not `"action"` → ignore silently. Otherwise decode with `ProtocolCoding.decodeRequest`; invalid → `error bad_json`; unknown action → `unknown_action`; cooldown (`ProtocolV1.actionCooldown`, or `sensitiveCooldown` for `sensitiveActions`) → `cooldown`; else call `ActionRunner` and reply `actionResult` **within 1 s** (long actions reply `ok:true, message:"Working on it"` right away and finish in the background). Send status every 1 s. Handle listener failure (port in use) by showing it in the UI.
- **ActionRunner.swift**: action keys = `["text_mom","volume_up","call_back","demo_48h","help","calendar","focus_music"]`. This phase: always dry run → `ok:true, dryRun:true, message:"Dry run: <action>"`. Structure it so Phase 2 can add real kinds (imessage, volume, music, shortcut, say). Loads `~/.silentspeech/actions.json` if present (ignore errors). `actions.example.json` shows the future shape: `{ "text_mom": { "kind": "imessage", "to": "+15555550100", "text": "On my way!" }, ... }`.
- **App.swift**: `@main` App, one window. `ProcessInfo.processInfo.beginActivity(options: [.userInitiated, .idleSystemSleepDisabled], reason:)` so App Nap doesn't stop streaming in the background.
- **ContentView.swift**: shows headphones state, auth, bud, live Hz, gap %, clients count, port status; toggles **Simulate motion**, **Allow non browser clients** (dev, off by default) and **Armed** (off by default; armed changes go out in `status` and future `hello`); last 20 log lines (connections, actions). A "Open dashboard" link to `https://spiro-12.github.io/weekend-projects/01-silent-speech/?mode=live`.
- Keep everything on the main actor / main queue where it touches UI state. Use `DispatchQueue.main.async` from the motion queue and NWConnection callbacks.

## Signing (permissions must stick across rebuilds)
Ad hoc signing (`-`) makes macOS forget Motion/Automation permissions on every rebuild, so Spiro would have to click Allow again each time. Preferred: a **stable local self signed code signing identity** named `SilentSpeech Local` created once on Spiro's Mac (openssl cert with code signing EKU → import into the login keychain → trust for code signing; may need his password once). `project.yml` keeps `CODE_SIGN_IDENTITY: "-"`; SETUP.md builds with `CODE_SIGN_IDENTITY="SilentSpeech Local"` on the xcodebuild command line once that certificate exists (CI uses `CODE_SIGNING_ALLOWED=NO`). Fallback: ad hoc. Last resort: Spiro adds his Apple ID in Xcode once (Personal Team). Put the exact commands in SETUP.md.

## SETUP.md (for the Claude session running on Spiro's Mac; short, numbered)
`brew install xcodegen` → `cd mac && xcodegen` → `xcodebuild -project SilentSpeechBridge.xcodeproj -target SilentSpeechBridge -configuration Debug build` (add `CODE_SIGN_IDENTITY="SilentSpeech Local"` once the cert exists, else ad hoc) → `open build/Debug/SilentSpeechBridge.app` → Spiro clicks Allow on Motion. Test: Simulate on, open the dashboard with `?mode=live`, see ~50 Hz (Simulate) or 25 to 50 Hz (AirPods). Then AirPods in, Simulate off. Troubleshooting: AirPods must be the Mac's audio output and in ear; `tccutil reset AppleEvents com.spiro.SilentSpeechBridge`; port in use → quit other copy; try Chrome if Safari blocks ws://localhost.
